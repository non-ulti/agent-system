# Load Context (세션 핸드오프 복원)

이전 세션이 슬러그로 저장한 핸드오프를 읽어, 그 작업이 걸친 repo(들)의 현재 상태와 대조한 뒤 브리핑한다. **자동으로 작업을 재개하지 않는다** — 사용자가 명시적으로 지시하면 그때 시작한다.

핸드오프의 단위는 repo가 아니라 작업(슬러그)이다. 한 작업이 여러 repo에 걸칠 수 있고, 그 repo 목록은 핸드오프 본문의 "작업 repo"(옛 양식은 "관련 repo")에 있다.

## When to Use

- 새 세션에서 지난 작업을 이어갈 때
- 사용자가 "이어서 하자", "load context", "지난번 거 복원"을 요청할 때

## 절차

0. **어떤 핸드오프를 복원할지 고른다.** 핸드오프는 `~/.claude/agent-system/handoffs/<슬러그>.md`에 저장되고, 중앙 색인(`~/.claude/agent-system/handoffs.tsv`)이 그 목록을 모은다. 색인 컬럼은 `슬러그 \t 저장시각 \t 목표 \t 상태 \t 관련repo` 5개다(옛 양식은 4개 — 그때는 3번째 칸에 목표와 상태가 섞여 있으니 그대로 보여준다).
   ```bash
   IDX="$HOME/.claude/agent-system/handoffs.tsv"
   [ -s "$IDX" ] && cat "$IDX"
   ls "$HOME/.claude/agent-system/handoffs/"*.md 2>/dev/null     # 색인에 없는 고아 파일 확인용
   ```
   - **사용자가 인자(슬러그 일부/목표 키워드)를 줬으면** 색인 1번째 칸(슬러그)과 대조해 하나로 좁힌다. 정확히 하나면 그걸 대상으로, 여럿이 맞으면 후보만 보여주고 고르게 한다.
   - **인자가 없으면:**
     - 색인 항목 0개 → "저장된 핸드오프가 없습니다."로 종료한다. (없는 것은 오류가 아니다)
     - 1개 → 그 항목을 대상으로 한다.
     - 2개 이상 → `번호) 슬러그 · 저장시각 · 목표 · 상태 · 관련repo` 목록을 사람이 읽기 좋게(표) 보여주고, 사용자가 번호를 고를 때까지 기다린다. **자동 선택 금지.** 오늘 날짜가 상태 칸의 약속("9/4 복귀")과 맞는 항목이 있으면 그 사실만 짚어 준다.
   - 목록을 보여줄 때 **정리 후보**를 함께 알린다: 저장시각이 30일 넘은 항목, 그리고 `handoffs/`에 있는데 색인에 없는 고아 파일. "끝났으면 `save-context --done <슬러그>`로 보관할 수 있다"고 한 줄만 덧붙이고, 이동·삭제는 사용자가 시키기 전엔 하지 않는다.
   - 고른 항목의 슬러그를 `SLUG`로 삼는다(아래 1·2번에서 사용).

1. **핸드오프 파일을 읽는다.**
   ```bash
   cat "$HOME/.claude/agent-system/handoffs/$SLUG.md" 2>/dev/null
   ```
   - 색인엔 있으나 파일이 없으면(색인이 낡음): "색인엔 있으나 핸드오프 파일이 사라졌습니다"라고 알리고, 그 줄을 색인에서 지울지 제안한 뒤 다시 고르게 한다. 색인 줄 삭제는 `awk -F'\t' -v s="$SLUG" '$1!=s' "$IDX" > "$IDX.tmp" && mv "$IDX.tmp" "$IDX"`.
   - 색인이 아예 없으면: "저장된 핸드오프가 없습니다."로 종료한다.
   - 본문 `- 저장:` 시각과 색인 저장시각이 다르면 브리핑에 표시한다(어느 쪽이 나중 것인지 포함).

2. **현실 검증** — 핸드오프는 "쓰인 시점의 진실"이므로 현재와 대조한다.

   **작업 repo** 각각에 대해:
   ```bash
   git -C <repo> log -1 --pretty='%h %s' 2>/dev/null       # 현재 커밋 (해시 + 제목)
   git -C <repo> rev-parse --abbrev-ref HEAD 2>/dev/null   # 현재 브랜치
   git -C <repo> log --oneline <핸드오프-커밋>..HEAD 2>/dev/null  # 저장 이후 커밋들 (주1)
   git -C <repo> status --short 2>/dev/null                # 미커밋 변경 (주2)
   git -C <repo> diff --stat 2>/dev/null | tail -1
   ```
   - 주1: `<핸드오프-커밋>` 자리에는 그 repo 항목의 "마지막 커밋" short hash를 대입한다. 없으면 이 명령은 건너뛴다. 그 해시가 현재 히스토리에 없으면(rebase/squash/amend 등) "저장 시점 커밋을 현재 히스토리에서 찾을 수 없음"을 브리핑에 표시한다.
   - 주2: 핸드오프의 "미커밋" 목록·"규모"와 지금 결과를 **파일 단위로 대조**한다. 저장 시점엔 없던 파일이 생겼거나, 같은 파일인데 `diff --stat` 숫자가 달라졌으면 "저장 이후 누가 더 만졌다"는 뜻이니 그 파일을 짚는다. 옛 양식 핸드오프라 기준값이 없으면 "기준값 없음 — 소유 구분 불가"로 표시하고 그럴듯하게 추정하지 않는다.
   - 브랜치·커밋이 핸드오프와 다르면(저장 이후 커밋이 쌓였거나 브랜치가 바뀜) 그 사실을 브리핑에 명시한다.

   **주변 repo**(있을 때): 적힌 "주의" 조건만 확인한다(예: 미추적 파일이 아직 있는지, stash가 살아 있는지). 브랜치나 커밋이 바뀐 것은 이 repo에선 경보가 아니다 — 작업 대상이 아니라서 넣은 항목이다. 옛 양식에서 "관련 repo"에 "이 작업 아님"이라 적힌 항목도 같은 취급을 한다.

   **외부 참조**(있을 때): MR·Confluence·지라는 자동으로 조회하지 않는다(사내망·인증이 필요하고, 조회 자체가 부작용일 수 있다). 브리핑에 "저장 시점 상태 그대로, 지금은 미확인"으로 표시하고, 사용자가 확인을 원하면 그때 조회한다. 확인 수단이 이 세션에 있으면(MCP·CLI) 그 사실만 알린다.

   **파일 존재**: "다음 할 일"이나 "현재 상태"가 언급하는 로컬 파일·디렉토리가 실제로 존재하는지 확인하고, 없으면 표시한다. 코드 repo가 없는 조사 작업이면 git 대조는 건너뛰고 산출물·참조 파일 존재만 확인한다.

3. **브리핑한다.** 다음을 요약해 사람이 읽기 좋게 제시한다:
   - 목표 / 현재 상태 / 다음 할 일 (핸드오프에서). 다음 할 일은 "왜"까지 같이 옮긴다 — 근거를 떼고 옮기면 사용자가 "그건 왜 하는데?"를 다시 묻게 된다
   - 작업 repo가 여럿이면 각 repo의 검증 결과를 구분해서. 주변 repo는 "주의 조건 유효/해소"만
   - 검증 결과 어긋난 점(있으면) — "저장 이후 커밋 3개", "e2e-testing.md가 저장 시점 +2줄에서 지금 +15줄로 늘었음(누가 만졌는지 확인 필요)" 등 구체적으로
   - 외부 참조는 "미확인" 표시와 함께
   - 정리 후보(30일+, 고아 파일)가 있었으면 한 줄

4. **지시를 기다린다.** 자동으로 다음 할 일을 실행하지 않는다.

## 원칙

- 핸드오프 내용을 그대로 믿지 말고 항상 현재 상태와 대조한다. 오래됐거나 다른 머신/세션의 작업이 끼어들었을 수 있다.
- **읽은 것·검증한 것만 전달하고, 빈칸을 추측으로 메우지 않는다.** 핸드오프에 없거나 모호한 부분을 그럴듯한 해석으로 단정하지 말 것. 핸드오프와 현재 상태가 어긋나거나 불명확하면 매끄럽게 넘기지 말고 "불명확/검증 필요"로 드러낸다. 추론을 전할 땐 확인된 사실과 구분해 표시한다.
- 브리핑은 짧게. 다음 할 일의 첫 항목을 또렷하게 전달한다. 핸드오프 원문이 길면 요약하되, 어긋난 점과 "왜"는 줄이지 않는다.
